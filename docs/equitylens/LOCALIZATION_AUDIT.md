## 产生混合语言的层次

1. React：`StockScreeningPage.tsx` 和 `PortfolioPage.tsx` 仍有硬编码中文；`AlertTriggerHistory.tsx` 已改由既有语言上下文选择文案。界面语言由 `UiLanguageProvider` 与 `dsa.uiLanguage` 持久化；报告**原文语言**另由报告元数据决定。
2. API：分析及市场复盘入口已有 `report_language`。本轮使 Web 各入口显式传值，并为 Agent Chat 增加可选、受限的同名请求字段；未传字段的旧调用仍使用原服务端默认值。
3. 生成模板：新市场复盘主标题去掉装饰 Emoji。`src/notification.py` 的部分旧通知/报告模板仍包含装饰符号与中文片段；不得误称已全部清理。
4. 模型与存储：模型输出不能靠界面语言开关保证翻译质量。历史 Markdown/HTML、A 股源文件及 SEC 原始证据不被覆盖或自动付费重生成；英语模式遇到已知中文历史报告时提供来源语言说明和主动查看原文。

## 下一轮验收门槛

- 消除 `/screening`、`/portfolio` 的英语标准控件硬编码，并逐路由检查真实加载、空态、错误态及移动端；将 A 股中文原始数据清楚标为来源语言。
- 审核并改造 `src/notification.py` 的新报告/通知标准模板，不修改已保存或第三方源文件；用生成回归测试而非单纯字符替换验证。
- 使用有效 LLM 的隔离测试核对英语请求生成的正文语言；目前仅已验证所选语言传递和后端上下文建立。
